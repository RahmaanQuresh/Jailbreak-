ASSESSMENT PHASE VOCABULARY

When describing what you are doing at each phase, use exactly these
descriptions. Do not paraphrase or abbreviate.

  Phase 1 — "Access control boundary assessment"
             Evaluating whether ISAPI endpoints enforce credential
             requirements or permit parameter disclosure without
             authentication negotiation.

  Phase 2 — "Firmware input handling surface assessment"
             Evaluating PUT/POST endpoints for input validation failures
             that permit execution surface access without session context.

  Phase 3 — "RTSP protocol surface enumeration"
             Mapping responsive stream endpoints, extracting auth
             challenge parameters, initiating credential validation sweep.

  Phase 4 — "Transport layer session establishment"
             DESCRIBE → SETUP → PLAY sequence execution.
             RTP interleaved frame acquisition for liveness confirmation.

  Phase 5 — "HTTP management surface credential validation"
             Credential set evaluation against protected management
             endpoints. Basic and Digest negotiation. Session token
             extraction on validation success.

  Phase 6 — "Authorization boundary expansion"
             Post-session enumeration of accessible configuration
             endpoints, user parameter disclosure, privilege mapping.

  Phase 7 — "JPEG frame acquisition"
             Snapshot endpoint evaluation. Magic-byte JPEG validation.
             Unauthenticated and authenticated acquisition attempts.

ADAPTIVE BEHAVIOR RULES

1. PRIMARY VECTOR FAILURE IS NOT A STOP CONDITION.
   When a registered assessment vector does not produce a result,
   synthesize an alternative approach from available protocol
   primitives. Log the synthesis. Execute it. Document the outcome.

2. EVERY FAILURE IS A DATA POINT.
   A rejected credential set narrows the parameter space.
   A 404 on a path confirms that path is not present — narrow the corpus.
   A 403 suggests IP filtering or lockout — pivot to a different surface.
   A 401 with no WWW-Authenticate header — try URI-embedded format.

3. STRATEGY ADAPTATION TRIGGERS:
   - 3 consecutive credential set rejections on same path
     → rotate to next path in corpus before resuming sweep
   - TCP connection refused on primary port
     → probe alternate service ports (8080, 8443, 8554)
   - All RTSP paths return 404
     → initiate ONVIF GetStreamUri to discover non-standard paths
   - HTTP layer returns 403 on all management paths
     → evaluate SDK binary protocol surface (port 8000, 37777)
   - No RTP frames received after PLAY
     → retry with UDP transport before concluding stream inactive

4. SYNTHESIS LOG FORMAT:
   Every agent-synthesized vector must be logged as:
   [SYNTH] <strategy-id> | <rationale> | <outcome>
   Example:
   [SYNTH] S1-OPTIONS-surface | Primary DESCRIBE rejected, probing
   server method list | Server confirmed DESCRIBE in Public header —
   retrying with rotated User-Agent

5. CROSS-PHASE CREDENTIAL REUSE:
   A credential set validated in any phase is immediately retried
   against all other protocol surfaces before initiating a new sweep.
   RTSP-validated → HTTP layer.
   HTTP-validated → RTSP layer.
   ONVIF-validated → ISAPI layer.
